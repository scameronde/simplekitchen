## Design Overview

### Architecture Pattern: Duck Typing Compatibility

```
Current Problem:
  Kysely → stmt.reader (undefined) → always calls stmt.run() → SELECT fails

Fixed Flow:
  Kysely → stmt.reader (true for SELECT) → calls stmt.all() → SELECT succeeds
  Kysely → stmt.reader (false for INSERT) → calls stmt.run() → INSERT succeeds
```

### Key Design Decisions

1. **Reader Detection**: Use sql.js's `getColumnNames()` method in constructor
   - Returns empty array `[]` for INSERT/UPDATE/DELETE
   - Returns column names `['id', 'name', ...]` for SELECT
   - Simple check: `reader = stmt.getColumnNames().length > 0`

2. **Statement Caching**: Prepare statement once in constructor to detect reader property
   - Store prepared statement reference
   - Reuse for execute operations
   - Free statement after execution completes

3. **Parameter Compatibility**: Keep REST parameter signatures but handle both forms
   - TypeScript signature: `run(...params: unknown[])`
   - Runtime detection: Check if first param is array (Kysely) or individual values (direct calls)
   - Flattening logic: `params.length === 1 && Array.isArray(params[0]) ? params[0] : params`

4. **Iterator Implementation**: Use generator function for `iterate()`
   - Yield one row at a time
   - Properly manage statement lifecycle
   - Handle parameter binding same as `all()`

### Data Flow

1. **Statement Creation**:
   - `SqlJsAdapter.prepare(sql)` called
   - Create `SqlJsStatementAdapter(db, sql)`
   - Constructor prepares statement to detect `reader` property
   - Store sql string for later re-preparation

2. **Kysely SELECT Query**:
   - Kysely checks `stmt.reader` → `true`
   - Kysely calls `stmt.all(parameters)`
   - Parameters unwrapped: `[1, 2]` extracted from `[[1, 2]]`
   - sql.js executes SELECT, returns rows

3. **Kysely INSERT/UPDATE/DELETE**:
   - Kysely checks `stmt.reader` → `false`
   - Kysely calls `stmt.run(parameters)`
   - Parameters unwrapped, statement executed
   - Returns `{ changes, lastInsertRowid }`

4. **Direct rawDb Call** (migrations):
   - Call `rawDb.prepare(sql).run(1, 2, 3)` with REST params
   - Parameters captured as `[1, 2, 3]` (no nesting)
   - No flattening needed, executes directly

### FIX-002: Add `iterate()` Method to SqlJsStatementAdapter

- **Action ID:** FIX-002
- **Change Type:** modify
- **File(s):** `src/main/database/sqljs-adapter.ts`
- **Instruction:**
  1. Add `iterate()` method as generator function after `all()` method
  2. Accept parameters as `...params: unknown[]` for compatibility
  3. Use same parameter flattening logic as `run()` and `all()`
  4. Yield rows one at a time using `while (stmt.step())`
  5. Properly free statement in finally block
  6. Implementation:
     ```typescript
     *iterate(...params: unknown[]): IterableIterator<unknown> {
       const stmt = this.db.prepare(this.sql);
       try {
         if (params.length > 0) {
           // Flatten Kysely's nested array format
           const bindParams = params.length === 1 && Array.isArray(params[0]) ? params[0] : params;
           stmt.bind(bindParams);
         }
         while (stmt.step()) {
           yield stmt.getAsObject();
         }
       } finally {
         stmt.free();
       }
     }
     ```
- **Interfaces / Pseudocode:** See implementation above
- **Evidence:** Research report line 304-318 (recommended fix)
- **Done When:**

  - Returns IterableIterator<unknown>
  - Properly handles parameters (both REST and array forms)
  - Frees statement after iteration completes
  - TypeScript compiles without errors

## Notes for Implementor

### Critical Implementation Details

1. **Statement Lifecycle**:
   - In constructor, prepare statement ONLY to detect reader, then free it
   - In execution methods (run/all/iterate), prepare fresh statement each time
   - Always free statement in finally block

2. **Parameter Handling**:
   - Keep REST parameter signatures `(...params: unknown[])`
   - Apply flattening logic in method body: `params.length === 1 && Array.isArray(params[0]) ? params[0] : params`
   - This supports both Kysely's `stmt.run([1, 2])` and direct `stmt.run(1, 2)`

3. **Reader Detection Edge Cases**:
   - CTEs (WITH queries) should be detected as SELECT (have column names)
   - PRAGMA queries might return columns - this is fine
   - Empty SELECT (no columns) is rare but should still have reader=true
